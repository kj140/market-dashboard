- 作成日: 2026-11-12
- 状態: ドラフト（ユーザー承認待ち）
- 表記: 「**ユーザー決定**」はユーザーが会話で決めたこと、「**設計者判断**」は Claude が決めてユーザーに提示したこと（ユーザーが覆してよい）。

## 1. 目的と背景

### 何のためのものか
朝の通勤中にスマホで開き、数十秒で「今日は買い増すか・様子見か・少しずつ利確してキャッシュを増やすか」を判断するための1枚のWebページ。**分野ごとのキャッシュ比率の目安**と、**銘柄ごとの判定と理由**を出す。（ユーザー決定）

### 背景
- ユーザーは YouTube の市場解説動画（マーケット超分析）の見方をもとに、指標と判定ルールの設計書を持っていた（Fear & Greed の段階エントリー、SOX の -30%・35営業日、名目GDP−10年債スプレッド、10年債4.5%超え日数、CPI 3.5%ルール、TOPIX 予想PER 13.7倍 等）。
- それを元に別のAIが作ったダッシュボード2版を評価した結果、次の問題があった。この設計はこれらを繰り返さないことを最優先にする。
  1. 初版は実データを一切取得しておらず、全値が手入力の固定値だった。
  2. 第2版（Python + data.json）は、CNN（HTTP 418 で拒否）と FRED（タイムアウト）の取得に失敗すると、**動画時点の数値を黙って代入**し、画面上は「実データ読込」と表示していた。判定材料の半分以上が固定値なのに気づけない。
  3. 判定ロジックが仕様とずれていた（SOX の日柄条件なし、CPI の境界、4.5% 未満でも警告が出る等）。
- 第2版の `fetch_market_data.py` は参考資料（ユーザーの `Downloads\market_dashboard_package.zip`）。取得部分は流用してよいが、上記の問題を直すこと。

### 成功の姿
- 毎朝、PCを起動しなくても自動で最新化され、スマホのホーム画面から1タップで開ける。
- 開いて10秒以内に、3分野の比率・前日からの変化・判定が変わった銘柄がわかる。
- 表示されている数値が「本物の最新値か、古い値か、取れなかったか」が必ずわかる。
- 判定が変わった日だけ Gmail に通知が来る。

## 2. ゴール／ノンゴール／アンチゴール

### ゴール
- 3分野（米国株・日本株・半導体）それぞれのキャッシュ比率の目安を毎日算出・表示する。（ユーザー決定）
- 対象7銘柄それぞれに判定と理由を表示する。（ユーザー決定）
- キャッシュ比率の推移を折れ線グラフで表示する（1か月／3か月／1年）。（ユーザー決定）
- 判定や比率が変わったら Gmail で通知する。（ユーザー決定）
- スマホから外出先で見られる。（ユーザー決定）

### ノンゴール
- 保有株数・金額・損益の管理（ページは公開のため載せない）。
- 自動売買、証券口座との連携。
- What-if 用のスライダーや手動シミュレーション（通勤中には不要。設計者判断）。
- 日中のリアルタイム更新（1日1回で十分）。
- 投資助言としての保証。ページに「個人の判断補助であり投資助言ではない」旨を小さく表示する。

### アンチゴール（動いていても失敗とみなすもの）
- **取得に失敗した値を、別の固定値で黙って埋めて正常に見せること。** 最重要。
- 指標が多すぎて判断に時間がかかる画面（「あまり難しいものではないように」ユーザー要望）。
- 毎日のように判定が行ったり来たりして、通知が無意味になること。
- 古いデータ（更新が止まった状態）を、最新のように表示すること。

## 3. 制約

- **費用ゼロ**で運用する（GitHub 無料プラン、FRED 無料 API キー、Gmail）。
- **リポジトリと GitHub Pages は公開**（無料プランの Pages は公開リポジトリが前提）。ユーザーは公開を了承済み。
  - したがってリポジトリにも画面にも保有情報・個人情報・メールアドレスを置かない。
  - API キー、Gmail のアプリパスワード、通知先アドレスは GitHub Secrets に置く。
  - 検索エンジンに載らないよう `<meta name="robots" content="noindex,nofollow">` と `robots.txt`（Disallow: /）を入れる。
- Yahoo / CNN のデータは利用規約上の再配布がグレー。個人用の非告知ページとして運用する（URL を広めない）。
- PC 不要で毎朝動くこと → GitHub Actions のスケジュール実行。
- GitHub Actions のスケジュール実行は数分〜数十分遅れることがある。許容する。

## 4. 全体構成（設計者判断）

```
GitHub Actions（毎朝 06:30 JST = 21:30 UTC 前日）
  └ Python: 取得 → 指標計算 → 分野スコア → キャッシュ比率 → 銘柄判定・理由
      ├ docs/data/latest.json     … 今日の全結果（各指標の取得状態つき）
      ├ docs/data/history.json    … 日次の比率・判定の履歴（追記）
      ├ 前日との差分があれば Gmail 送信（SMTP + アプリパスワード）
      └ 変更を main に commit & push
GitHub Pages（main ブランチの /docs を公開）
  └ index.html + JS: latest.json と history.json を読んで描画
```

- 計算はすべて Python 側で行い、ページは表示だけ（ページ側に判定ロジックを持たない）。判定ロジックが2か所に分かれてずれる事態を避けるため。
- 設定ファイル（後述の `config/`）を GitHub のWeb画面から編集すれば、閾値や手入力値を変えられるようにする。
- 手動実行（workflow_dispatch）もできるようにする。

### Google ではなく GitHub にした理由（設計者判断）
Google Apps Script + Google サイトも検討したが、Google のサーバーからは Yahoo などの株価取得を拒否されやすい。既存の Python 取得処理も流用しやすい GitHub を選んだ。ユーザーは「Google サイトにこだわりはない、スマホから見られれば良い」と回答済み。

## 6. データ取得

### 6.1 取得元と指標

| 指標 | 取得元 | ID / 方法 | 頻度 | 使う分野 |
|---|---|---|---|---|
| S&P500, NASDAQ100, SOX, 日経平均 | Yahoo (yfinance) | `^GSPC` `^NDX` `^SOX` `^N225` | 日次 | 各分野 |
| 対象7銘柄の株価 | Yahoo | 上表 | 日次 | 銘柄判定 |
| ドル円 | Yahoo | `JPY=X` | 日次 | 日本 |
| WTI 原油 | Yahoo | `CL=F` | 日次 | 共通ブレーキ |
| CNN Fear & Greed | CNN | `production.dataviz.cnn.io/index/fearandgreed/graphdata` | 日次 | 米国・半導体 |
| 米10年債利回り | FRED 公式API | `DGS10` | 日次 | 米国・共通 |
| 名目GDP | FRED | `GDP`（前年同期比を計算） | 四半期 | 共通 |
| CPI | FRED | `CPIAUCSL`（前年同月比を計算） | 月次 | 共通 |
| 実効FF金利 | FRED | `EFFR` | 日次 | 参考表示 |
| 民間設備投資 | FRED | `PNFI` ÷ `GDP` × 100 | 四半期 | 半導体 |
| TOPIX 12か月先予想PER | **手入力** | `config/manual.yaml` | 週次（ユーザーが更新） | 日本 |
| SOX 12か月先予想PER | **手入力** | `config/manual.yaml` | 週次（ユーザーが更新） | 半導体 |

- FRED は第2版で使っていた公開CSV（fredgraph.csv）ではなく、**公式API（無料キー、`FRED_API_KEY` を Secrets に）** を使う。タイムアウトは長め（30秒程度）にし、リトライを2回入れる。
- SOX の予想PERは、yfinance の ETF の `forwardPE` が取れないことが多いため手入力にする（設計者判断）。
- CNN は GitHub のサーバーからだと拒否される可能性が高い。拒否されたら「取得失敗」として扱い（6.2）、代わりの値は入れない。代替の取得手段を探すのは builder に任せる。ただし**無関係な値で埋めることは禁止**。
- 自然利子率 r*、AI普及率、ハイパースケーラーの設備投資計画、債務上限などイベント系は今回は入れない（画面を簡単にするため。設計者判断）。

### 6.2 取得状態の扱い（最重要）

各指標に必ず次のどれかの状態を付けて `latest.json` に保存し、画面にも表示する。

| 状態 | 意味 | 判定に使うか | 画面表示 |
|---|---|---|---|
| `live` | 今回の実行で取得できた | 使う | 通常 |
| `stale` | 今回は取得失敗。前回成功時の値と日付を使う | 前回成功から一定期間内なら使う（日次指標は3営業日、月次・四半期は次回公表まで） | 「前回値（11/08）」と明示 |
| `manual` | 手入力値 | 使う | 「手入力（11/05更新）」と明示。入力から14日を超えたら警告色 |
| `missing` | 取れず、使える前回値もない | 使わない | 「取得失敗」と明示 |

- 「前回成功時の値」は `latest.json` の前回分（または history）から引き継ぐ。**ハードコードした既定値は一切持たない。**
- 月次・四半期の指標は、FRED の最新観測日をそのまま表示する（例：CPI 2026-09）。最新値が古いのは公表周期のためで、失敗ではない。
- ページ上部に「最終更新 11/12 06:31」を表示する。最終更新から36時間以上経っていたら赤い警告帯を出す（Actions が止まったことに気づくため）。

## 7. 判定ロジック

### 7.1 キャッシュ比率のものさし（ユーザー決定）

| 状態 | キャッシュ比率 |
|---|---|
| 最も強気（大底サインが重なる） | 0%（使い切る） |
| 普段（シグナルなし） | 20% |
| 最も警戒（危険サインが重なる） | 90% |

### 7.2 スコアから比率への変換（設計者判断）

- 各分野で、使える指標ごとに「点数」を出して合計する。マイナスが強気（キャッシュを減らす）、プラスが警戒（キャッシュを増やす）。
- 合計点を次の段階表で比率に変換する。比率は5段階刻みの決まった値だけを取る（毎日小刻みに動かないように）。

| 合計点 | 比率 |
|---|---|
| -6 以下 | 0% |
| -5 〜 -3 | 10% |
| -2 〜 +1 | 20%（普段） |
| +2 〜 +3 | 35% |
| +4 〜 +5 | 50% |
| +6 〜 +7 | 70% |
| +8 以上 | 90% |

- **行ったり来たり防止**：比率を上げる方向は即日反映し、下げる方向は2回連続の「評価日」（7.5）で条件を満たしたら反映する（警戒は早く、戻りは慎重に。「徐々に利確」という意図に合わせた設計者判断）。
- 点数表・段階表・閾値はすべて `config/rules.yaml` に置き、コードを触らずに調整できるようにする。下記の点数は初期値。

### 7.3 指標ごとの点数（初期値。設計者判断。ルールの出典はユーザーの設計書＝動画の見方）

**米国株**
| 指標 | 条件 → 点数 |
|---|---|
| Fear & Greed | ≤9: -3 / ≤10: -2 / ≤20: -1 / 21〜69: 0 / 70〜80: +2 / >80: +3 |
| NASDAQ100 52週高値からの下落率 | 10〜15%: -1（強気相場内の健全な押し目） / 15%超: 0 / 10%未満: 0 |
| 10年債 4.5%超え経過営業日数 | 4.5%未満: 0 / 1〜30営業日: +1（短期逆風） / 31〜89: 0 / 90営業日以上: -1（織り込み完了） |

**日本株**
| 指標 | 条件 → 点数 |
|---|---|
| 日経平均 52週高値からの下落率 | 10〜20%: -1 / 20%超: -2 / 10%未満: 0 |
| TOPIX 予想PER（手入力） | ≤13.7倍: -2（過去2回しかない底値水準） / ≤14.5: -1 / ≥16.5: +1 / ≥17.5: +2 |
| ドル円 1か月変化率 | 円高 5%以上: +2 / 円高 3〜5%: +1 / それ以外: 0 |

**半導体**
| 指標 | 条件 → 点数 |
|---|---|
| SOX 52週高値からの下落率 × 日柄 | 下落28%以上 かつ 高値から25〜45営業日: -3（歴史的底入れゾーン） / 下落28%以上（日柄外）: -1 / 15〜28%: 0 / 5%未満 かつ F&G 70以上: +2 |
| SOX 予想PER（手入力） | ≤15倍: -2 / ≤16: -1 / ≥22: +1 / ≥25: +2 |
| Fear & Greed | 米国株と同じ表 |
| 民間設備投資 ÷ 名目GDP | 20%以上: +3（過剰投資・バブル警戒） / 18〜20%: +1 / それ未満: 0 |

**共通ブレーキ（3分野すべての合計点に足す）**
| 指標 | 条件 → 点数 |
|---|---|
| 名目GDP前年比 − 10年債利回り | マイナス: +3（〇〇ショック警戒） / 0〜0.5%: +1 / それ以上: 0 |
| CPI 前年比 | ≥3.5%: +1（上値抑制） / 3.0〜3.4%: -1（適度なインフレ） / それ未満: 0 |
| WTI 原油 | ≥110ドル: +2 / 100〜110: +1 / それ未満: 0 |

- 10年債の「4.5%超え経過営業日数」は**連続日数**で数える。4.5%を上回った初日を起点にし、終値ベースで一度でも4.5%を下回ったら0にリセットする（ユーザーの元の設計書「4.5%以上となった初日を起点に営業日数をカウント」に従う）。
- `missing` の指標は0点として扱い、「判定に使えなかった指標」として画面に列挙する。
- 1つの分野で、点数を持つ指標（**共通ブレーキの3指標を含む**）の半分を超えて `missing` のときは、その分野を「**判定保留**」とする。半導体なら7指標中4つ以上が欠けた場合。（設計者判断）比率は前日の値のまま、グレー表示にする。この場合は判定変更の通知を出さず、代わりに取得失敗の通知を送る。

### 7.4 銘柄ごとの判定（設計者判断）

判定の種類：`買い増し` / `保有` / `利確 1/4` / `利確 1/3` / `利確 1/2`

基本は所属分野の比率で決める。

| 分野の比率 | 通常銘柄 | SOXL（3倍レバ） |
|---|---|---|
| 0〜10% | 買い増し | 買い増し |
| 20% | 保有 | 保有 |
| 35% | 保有 | 利確 1/3 |
| 50% | 利確 1/4 | 利確 1/2 |
| 70% | 利確 1/3 | 利確 1/2 |
| 90% | 利確 1/2 | 利確 1/2（実質全部の意味で「全利確」と表示） |

銘柄ごとの補正：
- 銘柄自身が52週高値から30%以上下がっており、分野の比率が35%以下なら、1段階強気寄りにする（例：保有→買い増し）。個別がすでに大きく調整している点を反映するため。
- キオクシア（メモリー）は、半導体の比率が35%以上のとき1段階警戒寄りにする（性質メモどおり）。
- 「利確 1/3」などの割合は、**その日の時点で持っている量に対する目安**として表示する。保有量は扱わない。

### 7.5 「1日」の数え方と実行日（設計者判断）

- Actions は毎日実行する。ただし、米国株（`^GSPC`）と日本株（`^N225`）の最新終値の日付がどちらも前回の評価から変わっていなければ、その実行は「**評価なし**」とする。履歴に追記せず、判定変更の通知も出さない（土日や日米同時の祝日に、同じデータで「2回連続」が成立するのを防ぐ）。
- **評価日** = 新しい市場データで評価した実行。「前日」は直前の評価日、「2回連続」は評価日2回、`stale` の「3営業日」も評価日3回で数える。
- 日米の祝日のずれは区別しない。片方の市場だけ新しいデータがあれば評価日とし、休場側は直近の終値を使う（これは `stale` ではなく `live` 扱い）。
- グラフの「1週前」「1か月前」は暦日で7日前・30日前に最も近い評価日を使う。
- 最終更新の警告帯（6.2）は「最後に**実行に成功した**時刻」で判定する。評価なしの実行も成功に含むので、週末でも36時間ルールのまま誤警告は出ない。

### 7.6 理由文（設計者判断）

- LLM は使わず、テンプレートで組み立てる（毎朝の自動実行で安定して同じ品質を出すため）。
- 分野の理由：点数が大きい順に最大3つの指標を「指標名 現在値（状態）」の形で並べる。例：「SOX 高値比-31.7%（底入れ目安到達）だが日柄99日で長期化／SOX予想PER 14.2倍で割安／10年債4.5%超え83日」
- 銘柄の理由：①その銘柄の高値比、②効いている分野の指標（上位1〜2個）、③性質メモ、を1〜2文でつなぐ。補正が効いた場合はそれも書く。
- `stale` や `manual` の値を使ったときは、理由文の中でもそうわかるようにする（例：「TOPIX予想PER 13.7倍（手入力 11/05）」）。

## 8. 履歴とさかのぼり計算

- `docs/data/history.json` に、日付ごとに「3分野の比率・合計点・各銘柄の判定」を追記する。
- **初回だけ過去1年分をさかのぼって計算**し、グラフが最初から埋まった状態にする（ユーザーに説明済み）。
  - 株価・ドル円・原油・FRED の系列は過去データがあるので、その日時点で入手できた値で計算する（FRED の月次・四半期は、その日時点で最新だった観測値を使う。公表遅れの厳密な再現までは不要）。
  - CNN Fear & Greed は graphdata に過去分が含まれていればそれを使う。取れなければその指標なしで計算する。
  - 手入力の PER は過去値がないので、さかのぼり計算では使わない。
  - さかのぼり計算した期間は、グラフ上で薄い色・点線などで「再計算値」とわかるようにする。
  - さかのぼり計算では「判定保留」ルールを適用しない（手入力PERとCNNが欠けると過去1年すべてが保留になり、グラフが横ばいになって点数表の調整に使えなくなるため）。使える指標だけで計算する。（設計者判断）
  - 手入力PERの有無で、さかのぼり期間と日々の運用で比率の基準が少しずれ、つなぎ目に段差が出ることがある。初回実行時、つなぎ目の日について「PERなしで計算した比率」も併記して記録し、段差の大きさが見えるようにする。

## 9. 画面（ユーザー決定：E案。モックアップでユーザーが選んだもの）

スマホ縦長1画面、ダーク配色。上から：

1. **ヘッダー**：最終更新時刻。古い場合は警告帯（6.2）。
2. **分野タブ**：`🇺🇸 米国 25%` `🇯🇵 日本 15%` `🔬 半導体 40%` のように、タブ自体に今日の比率を出す。前日から変わった分野のタブには小さな印を付ける。
3. **選択中の分野**
   - キャッシュ比率の目安（大きな数字）と、前日からの変化（▲10 など）。
   - **折れ線グラフ**：キャッシュ比率の推移。期間切替は 1か月／3か月／1年。縦軸は 0〜90%、「普段 20%」の点線を入れる。**今日（白）・前日（グレー）・1週前（紫）・1か月前（青）**の点を色違いで打ち、凡例に各時点の値を出す。
   - 主な理由（7.6）。
   - 判定に使えなかった指標や手入力値の古さがあれば、ここに注記する。
4. **銘柄リスト**（選択中の分野の銘柄）
   - 銘柄名、判定バッジ（色分け：買い増し＝緑、保有＝グレー、利確＝オレンジ）、現在値と高値比。
   - 判定が前日から変わった銘柄は「前日 保有 → 今日 利確 1/3」と表示する（A案で良いと言われた点）。
   - 理由文は常に全文表示する。
5. **指標の詳細**（折りたたみ。タップで開く）：各指標の現在値、取得状態、取得日、点数。
6. フッター：投資助言ではない旨の注記。

- 最後に選んだタブは端末に記憶する（localStorage。失敗しても動くようにする）。
- グラフのライブラリは builder に任せる（Chart.js 等の CDN 利用可）。
- スマホのホーム画面に追加しやすいよう、タイトルとアイコンを設定する。

## 10. 通知（ユーザー決定：Gmail）

- 送信手段：Gmail の SMTP（アプリパスワード）。送信元アドレス・アプリパスワード・送信先は Secrets（`GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `NOTIFY_TO`）。
- 送る条件：
  - いずれかの分野の比率が前日から変わった、またはいずれかの銘柄の判定が変わった → 「判定変更」通知。
  - 取得失敗は**状態が変わったときだけ**通知する。指標が `missing` になった日と、回復した日に1通ずつ送る。続いている間は送らない（CNN が恒常的に拒否された場合に毎日メールが届くのを防ぐ。設計者判断）。前回の各指標の状態は `latest.json` に保存して比較する。
  - 分野が判定保留になった日・解除された日も同様に1通ずつ送る。
  - 何も変わらない日は送らない。
- 件名の例：`【判定変更】半導体 30%→40% / SOXL 保有→利確1/3`（件名だけで要点がわかるように）。
- 本文：変わった項目と理由文、ページへのリンク。HTML メールでなくテキストで十分。
- さかのぼり計算の初回実行では通知を送らない。
